## Decisions log

Record notable decisions made during implementation here (date, decision, reason), so `DESIGN.md` can be updated to match.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-08 | Front matter settings use flat `scrald-theme` / `scrald-flavor` keys; nested `scrald:` map is read but never written (DESIGN §8.1, §16 Q1) | Obsidian's Properties panel can't display or edit nested maps; flat keys keep the minimal-edit YAML engine to top-level scalars |
| 2026-10-08 | Autosave off by default for v1; add close prompt and crash-recovery files in app data (DESIGN §9.3, §12, §16 Q2) | New edit/save path shouldn't write to user files unattended; recovery files cover crashes without touching the document |
| 2026-10-08 | Note transclusion is post-v1; v1 renders `![[Other note]]` as a link card (DESIGN §5.3, §16 Q3) | Keeps v1 scope down; transclusion raises cross-file source-range, editing, and cycle questions worth designing properly |
| 2026-10-08 | Windows first; macOS and Linux support is the final v1 milestone, M10 (DESIGN §11.1, §16 Q4) | Focus early work on one platform while keeping code portable so the port is mostly verification and packaging |
| 2026-10-08 | LF line endings for all repo files, enforced by `.gitattributes` (`eol=lf`) and `.editorconfig`; test fixtures exempt (`-text`) | Maintainer preference; also keeps diffs clean across platforms. Fixtures must keep CRLF/BOM bytes to test preservation |
| 2026-10-08 | `scrald-core` is tested on Windows, macOS, and Linux in CI from M0 (DESIGN §11.1) | Core has no GUI dependencies, so cross-platform CI is nearly free and catches portability slips early |
| 2026-10-08 | Manual Obsidian check (#15): nested `scrald:` map is read-only in Properties, flat keys editable; Obsidian property edits drop comments and turn flow lists into block lists, but keep key order and the nested map (DESIGN §8.1, §8.3) | Confirms the flat-key decision; the YAML editor must treat block lists as the common case |
| 2026-10-08 | YAML front matter parsed with `serde-saphyr` into an order-preserving `serde_json::Value` map (DESIGN §2) | Maintained and serde-based; `serde_norway` hasn't been updated since 2024-12 |
| 2026-10-08 | Block ranges start at column 1 and blocks are kept in source order, including footnote definitions (DESIGN §3) | Edits need indentation inside the range and ranges that tile the file; comrak otherwise moves footnotes to the end |
| 2026-10-09 | Bundled themes are TOML-only and compiled in; default theme follows the system light/dark mode; heading numbers computed in core (`data-number`) (DESIGN §7) | No resource bundling needed; CSS counters can't cross `content-visibility` sections |
| 2026-10-09 | Syntax highlighting in core at parse time (syntect, class output, palette colors); KaTeX, Mermaid, abcjs lazy in the frontend as named trusted renderers; npm override pins Mermaid's KaTeX to ours (DESIGN §4, §13) | Simpler than per-block highlight requests at ~18 ms/100K words; one KaTeX copy without the old version's advisories |
| 2026-10-09 | Flavors are comrak option profiles; many planned M4 "transforms" (inline footnotes, sub/superscript, definition lists, highlight, wikilink parsing, alerts, attributes, `:::` directives) are comrak built-ins; detection is a fenced-code-aware line scan with vault weighting (DESIGN §5) | Less custom AST code to maintain; detection stays instant |
| 2026-10-09 | Zoom and fit size only the reading column; resize restores the last scroll's anchor; a < 2 px sliver never counts as the block at the top (DESIGN §7.4) | UI chrome shouldn't scale with reading text; text rewraps before resize handlers run; device-pixel snapping otherwise let the anchor drift by a paragraph gap per zoom |
| 2026-10-09 | `docs/` is reserved for the user documentation site, a docsify site published with GitHub Pages (DESIGN §15) | Maintainer's plan; keeps user docs separate from design and developer docs at the root |
| 2026-10-09 | Obsidian syntax: comments blanked before parsing (offsets kept); callouts rendered last into one HTML block; vault index built per parse when needed; GFM keeps comrak alerts (DESIGN §5.4, §6.1) | Keeps source ranges exact; comrak's validator rejects wrapper nodes; per-parse scan costs little until large vaults show otherwise |
| 2026-10-09 | Pandoc: comrak parses attributes (`attributes` feature), Scrald renders them; fenced divs found by a Scrald pre-pass (fences blanked, outermost div = one block) instead of comrak directives; figures follow implicit-figure rules with `%` widths on the figure as the only allowed `style`; `Table:` captions grouped with their table; one `footnotes` list drives popovers and endnotes (DESIGN §5.4, §6.3, §13) | comrak's directives can't nest same-length fences; attributes must not become arbitrary inline styles; definition blocks stay in source order for editing |
| 2026-10-09 | Front matter editing uses a line scanner over top-level keys, not a YAML library's spans; unsupported shapes are read-only with a reason; properties panel open/closed is one global preference (DESIGN §8.2, §8.3) | A small scanner covers the editable shapes exactly and is easy to test by parsing results back; refusing anything else keeps edits from damaging files |
| 2026-10-10 | Front matter edits are unsaved until Ctrl+S (maintainer's choice): the app keeps each window's text, saves atomically, and asks before closing or leaving with unsaved changes; this brings M6's basic save path forward. Panel theme/flavor choices and "Save to document" clear the per-document database choice (DESIGN §7.6, §8.2, §9.3) | Keeps a human check between edits and the file; one save path for panel and block edits; otherwise the database choice would hide the new front matter value |
| 2026-10-10 | Block editing: CodeMirror 6 lazy-loaded; splices refuse stale ranges; undo/redo stores diffs (not snapshots) and unsaved is derived from the saved bytes; the reader updates in place with blocks keyed by content hash (DESIGN §9.1) | Small memory per undo step; no edit can land in the wrong place; unchanged blocks keep their DOM, which keeps a single-block edit near the 100 ms budget |
| 2026-10-15 | Raw mode: CodeMirror with the document's own line separator and text read via `sliceDoc()` (never `doc.toString()`); text synced to the app with version numbers; reader re-parses on exit (DESIGN §9.2) | `toString()` silently converts CRLF to LF, which a manual test caught; versions stop stale text from overwriting newer edits |
| 2026-10-16 | Faster re-render after an edit: a per-window render cache (sanitized HTML and highlighted code, keyed by exact input) and models that leave out HTML the window already shows, numbered so the window can ask for the whole model if it lost track (DESIGN §9.1) | A 100K-word edit went from about 100 ms to 50–65 ms. Caching only pure steps by their exact input can't show stale HTML, unlike caching whole blocks, whose HTML depends on the rest of the document |
| 2026-10-16 | Start screen: the state database stores each document's title and the theme it was last shown in (migration 2), so the recent list needs no file reads; only an existence check per entry, off the main thread. "Remove from list" forgets the document's row entirely; Open and drag and drop accept `.md`, `.markdown`, `.mdown`, `.mkd`, `.mkdn`, `.txt` (DESIGN §11) | Reading every recent file for its front matter would be slow on network drives and touches files the user didn't open; a removed entry shouldn't leave its reading position and settings behind |
| 2026-10-17 | Single instance: `tauri-plugin-single-instance`; a later launch opens its file in a new window of the running process (relative paths resolved in that launch's folder), or focuses the window already showing it; no file opens another start screen. With `SCRALD_DATA_DIR` set, the app identifier gets a per-folder suffix (DESIGN §11) | One document per process is never edited in two windows; test runs can't hand files to the user's real Scrald and database |
| 2026-10-17 | Installer and file associations: NSIS only, per-user; Tauri's `fileAssociations` is not used because its NSIS template overwrites each extension's default; an installer hook adds Scrald under `OpenWithProgids` and `RegisteredApplications` instead; publisher set to `torstees` (it defaulted to "github" from the identifier); no "make default" option in the installer or the app, since Windows lets only the user set it; build tools cached in `target/.tauri/` (DESIGN §11) | The installer must not take over `.md` without consent; Windows then offers Scrald in "Open with" and Default apps and asks the user |
| 2026-10-17 | Terminal theme import (Windows Terminal first): derived colors are chosen by WCAG contrast (links 4.5:1, accent 3:1, muted 4.5:1 or 75% of the text's own) and written explicitly into the new `theme.toml`; of the normal and bright ANSI variants, the more colorful readable one wins; selections must be solid and keep text readable; repeated imports get numbered names (DESIGN §7.3) | Terminal palettes are tuned for monospace text on a terminal background, not links and rules in prose; explicit values give the user something to adjust; Solarized-style palettes put grays in the bright slots |
| 2026-10-17 | More terminal formats: iTerm2, Alacritty (TOML only), Ghostty, kitty, base16/base24; detected by extension, else by content; iTerm2's XML plist read by a small scanner instead of the `plist` crate; base16 mapped to ANSI as base16-shell does (DESIGN §7.3) | `.itermcolors` files are always shallow XML, so a dependency (with its own four) wasn't worth it; Ghostty files have no extension and `.conf` is shared |
| 2026-10-17 | Google Fonts: downloaded in the background the first time a theme shows a family, once per run, with the fallback stack meanwhile; woff2 only from fonts.gstatic.com, every CSS value validated; all subsets kept with their unicode ranges; `font_cache` table plus files in the cache folder; served under the theme scheme with `Access-Control-Allow-Origin: *`; new dependency `ureq` (DESIGN §7.5) | Contacts Google only once per family; nothing from Google's CSS reaches the page unchecked; `ureq` is a small blocking client with rustls (no OpenSSL), and Tauri's `reqwest` isn't built on Windows; fonts across origins need CORS, which theme fonts were missing too |
| 2026-10-17 | Theme editor: a side panel from the switcher for user themes; changes previewed from the edited text in memory, written only on Save; edits applied with `toml_edit` (already in the dependency tree) to a fixed list of keys, keeping comments and layout; the result must parse as a theme before it's written (DESIGN §7.2) | Users' hand-written comments survive the editor; the editor can't produce a theme that won't load, or write keys it doesn't show |
| 2026-10-17 | Obsidian image embeds (`![[pic.png]]`) resolve like Markdown images: `assets:` folder, a path relative to the document, the document's folder, then the vault (DESIGN §6.1) | They only searched the vault index, which outside a vault is the document's folder alone, so `assets:` and subfolder paths were silently ignored |
| 2026-10-17 | Start screen covers and summaries: the cover comes from the first of the common cover keys (`cover`, `image`, `banner`, `heroImage`, Hugo's `images` and `cover.image`, ...), resolved like a document image; it and a one-line summary are stored in the state database (migration 4) on open and save; covers are served by token like document images, under a separate registry entry per window; `excerpt` joins the summary aliases (DESIGN §8.1, §11) | The list still never reads documents; covers can't expose files other than those the user's own documents name; a separate entry means refreshing the list never revokes an open document's images |
| 2026-10-18 | In-document search reads the text the reader shows from each block's sanitized HTML, not the Markdown source; core counts matches per block and footnote from a per-window index built on the first search, and the reader finds and paints the same matches with the CSS Custom Highlight API, near the viewport only (DESIGN §10) | Source text breaks phrases at formatting and matches inside URLs; counting in core keeps whole-document work off the main thread; custom highlights leave the blocks' content-keyed DOM untouched |
| 2026-10-18 | Keyboard shortcut reference: one list in `ui/src/shortcuts/shortcuts.ts`, shown in a dialog on `F1` or `Ctrl+/` (left to CodeMirror inside an editor, where it comments lines), from a ? button in the status bar, or a link on the start screen (DESIGN §10) | One list for the dialog and, later, the docs site; `F1` works everywhere, and `Ctrl+/` is what many editors use |
| 2026-10-18 | Reading progress counts words, not pixels: core adds a word count to each block (`Block.words`), and the status bar shows the share of words above the top of the screen with the time left, plus a thin line along its top edge; 100% once the end is on screen. Remote images can be blocked again from the status bar after **Load** (DESIGN §6.2, §10) | Section heights are estimates until laid out (`content-visibility`), so a scroll fraction would jump as sections mount; a short document is read as soon as it's shown; once loaded, remote images had no visible sign and no way back |
| 2026-10-18 | Headings inside fenced divs and raw HTML containers get TOC entries, ids, and outline numbers; the entry points at the group's block plus the heading's own offset, and a group with headings starts a section (DESIGN §3, §5.4) | Pandoc books often wrap each chapter in a div, which left them with an empty contents list; splitting the block would break editing and sanitizing of the container as a whole |
| 2026-10-18 | Settings dialog (`Ctrl+,`, ⚙ in the status bar, start screen link) for the global settings, each applied at once and announced to every window with a `settings-changed` event; the contents depth becomes a stored setting (`contents.depth`), and the default theme can go back to following the system. The status bar's autosave toggle is now an "Autosave" marker shown only while it's on (DESIGN §7.4, §7.6, §9.3, §10) | One place for settings that were spread across popovers and the status bar; applying at once matches the rest of the app, which has no Save buttons for preferences; a toggle that is off most of the time doesn't need room in the status bar |
| 2026-10-18 | Properties panel placement (`properties.placement`: top, left, or right), from a menu in the panel's header or the settings dialog. At the left it's a tab beside Contents; at the right, a sidebar of its own, which gives way to Contents (or the other way round, whichever was opened last) when the window is narrower than 64rem. `properties.open` now means "properties shown" in every placement, so it also remembers the left sidebar's tab. `Ctrl+Shift+\` shows or hides the properties. In a sidebar, a document without front matter can have properties added (closes the #143 follow-up); the sidebar is read-only in raw mode (DESIGN §8.2, §10) | Top placement takes room above the text on every document; a tab costs no width on small screens, and a sidebar of its own keeps both visible on wide ones. One open flag instead of one per placement keeps the settings small. Raw mode holds unsent text, and a property edit at the same time would be refused or overwrite it |
| 2026-10-19 | Accessibility pass: core checks a theme's colors against WCAG 2 AA (`theme/contrast.rs`: 4.5:1 for every text color on the page, sidebar, code, selection, highlight, tag chip, and callout tint; 3:1 for the accent), and a test holds the bundled themes to it, so the light themes' muted, syntax, and accent colors were darkened 2 to 18%. Keyboard focus shows as a 2px accent outline; modal dialogs keep Tab inside and give focus back on closing; the reading area is focusable and takes focus when a document opens; with reduced motion, CSS transitions are off too (DESIGN §7.2, §10) | Three of the five bundled themes fell just short of AA for muted text and syntax colors; a test keeps future edits honest. A themed outline is visible on every theme, unlike the browser's default; without a trap, Tab walked out of a dialog into the page behind it; a document opened with nothing focused, and Tab could never reach the reading area to scroll it |
| 2026-10-19 | An unclosed `<title>`, `<textarea>`, `<style>`, `<xmp>`, `<iframe>`, `<noembed>`, `<noframes>`, `<script>`, or `<plaintext>` in raw HTML is written as text before sanitizing; closed ones are still removed with their contents (DESIGN §13). The reader's automatic focus on open shows no outline (DESIGN §10) | A placeholder like `**Remove from <title>**` made the HTML parser read the rest of the list as the title's text, garbling it. GitHub's tag filter escapes these tags even when closed, but comrak 0.56 dropped it, and escaping closed ones would show the markup of embeds and scripts that Scrald has always removed quietly. The outline appeared around the whole reading area on every launch, because the browser counted the focus as keyboard focus |
| 2026-10-19 | Contrast warnings for any theme: **Check contrast** in the theme switcher, an automatic check after a terminal import, and a live Contrast section in the theme editor with ⚠ on the colors involved. Core's problems now name the theme colors they involve and carry a sample pair; ratios are cut, not rounded. Warnings never block loading or saving (DESIGN §7.2) | Hand-written themes and tweaked imports had no way to find out they were hard to read; a button covers themes the editor can't open (built-in, edited in a text editor), and the editor checks as you go so a fix shows at once. Blocking a save would stop people from saving work in progress |
| 2026-10-19 | New document (`Ctrl+N`, start screen): an optional title, a template, a file name, and a folder from the remembered ones (Settings) and recent documents' folders, defaulting to the last document's folder. Built-in templates add front matter only and set the flavor as the document's Scrald choice; user templates are `.md` files in `templates/`, with a sample written once. The title goes in through the minimal YAML editor. Files are created with `create_new`, and open in raw mode. Opening another document now always leaves raw mode (DESIGN §11, §12) | The maintainer asked for it, with remembered folders and "Remember this folder" unchecked by default. Placeholder body text in built-in templates would end up in files; the flavor in the state database keeps Obsidian notes free of a `scrald-flavor` property; one title-writing path keeps quoting identical to a property edit. Raw mode used to keep the previous document's text after `Ctrl+O` or Back, which could have written it into the next document |
| 2026-10-15 | Autosave: global setting, off by default, toggled in the status bar for now; saves 5 s after the user's last edit; never during a conflict; leaving or closing saves instead of asking (DESIGN §9.3) | Only the user's own edits start it, so loading the disk version or restoring recovered changes always gets a human check first |
| 2026-10-15 | Crash recovery: a 3-second background writer copies changed unsaved text to `recovery/<id>.recovery` (JSON header line + exact text); deleted on save, discard, or undo to the saved text; leftovers offered on reopen and listed when starting without a document; restore is an undoable edit (DESIGN §9.3) | Header-first format lists files without reading whole texts; per-window ids avoid two windows fighting over one file; writing off the UI path keeps typing unaffected |
| 2026-10-15 | Conflicts: banner with keep / load / compare; the disk version is snapshotted in the app so actions apply to what the user saw; "Load disk version" is an undoable edit; saves refuse to overwrite an unseen disk change; compare uses `@codemirror/merge` (DESIGN §9.3) | Nothing the user or another program wrote is lost without a decision; the save check closes the gap before the watcher's event arrives |
| 2026-10-09 | State store: SQLite in the app crate, `PRAGMA user_version` migrations, FNV-1a first-KB identity to reconnect moved files, in-memory fallback, `SCRALD_DATA_DIR` override (DESIGN §12) | Persistence is app-layer; stored hashes must be stable across Rust versions; automated runs must not touch real app data |
| 2026-10-08 | Work items tracked as GitHub issues: one parent issue per milestone with sub-issues, plus matching GitHub Milestones; TODO.md reduced to an index and this log | Maintainer already works this way and follows progress in a GitHub Project |
